Later stages can improve earlier distances

Stage k allows node k as an intermediate stop. It does not finalize node k.

The original directed graph

Filled nodes: allowed as intermediate stops. Thick outline: this stage’s k. Blue arrows: the selected route. Edge labels are original weights.

Distances after this stage

Rows = from, columns = to. ∞ = no allowed route yet. Green bold values changed this stage; outlined cell is the selected pair.

The key distinction: endpoints can be any nodes. Only the nodes between the endpoints must come from the allowed set.

Why we do not repeat stage 2

At stage 2, the route 3 → 2 → 4 is already allowed: 3 is an endpoint, and 2 is its only intermediate node.

At stage 3, combine 1 → 3 with that entire route 3 → 2 → 4. The result is 1 → 3 → 2 → 4, costing 3.

dist[1][4] ← min(11, dist[1][3] + dist[3][4])
= min(11, 1 + 2) = 3

“Through k” combines two routes, not necessarily two direct edges. Those routes already include earlier intermediate nodes.

for (k in 1..n) {         // allow one more intermediate node
    for (i in 1..n) {     // any starting endpoint
        for (j in 1..n) { // any destination endpoint
            // If both parts exist:
            dist[i][j] = minOf(dist[i][j], dist[i][k] + dist[k][j])
        }
    }
}

This example has positive weights. The usual shortest-path interpretation assumes no negative cycles.
