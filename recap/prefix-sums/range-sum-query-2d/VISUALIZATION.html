2D prefix sums: see the overlap

Your boundary idea now applies to both rows and columns. pre[r][c] covers the first r rows and first c columns.

How often each cell is counted

×1 included×2 double-counted×−1 over-subtracted×0 canceled / outside

Prefix table · boundary indexes

The two corrections

Construction: above + left count their shared corner twice. Subtract that corner once, then include the new cell.

Query: removing the top and left regions removes their shared corner twice. Add it back once. The corner's net count becomes zero.

Connect this to Kotlin and your boundary model

Matrix positions are zero-based, matching LeetCode. A query from (row1, col1) through (row2, col2) uses row boundaries row1 and row2 + 1, and column boundaries col1 and col2 + 1.

pre[row2+1][col2+1] − pre[row1][col2+1] − pre[row2+1][col1] + pre[row1][col1]

The original AcWing program used one-based cell positions. This view and the saved Kotlin implementation use LeetCode's interface; the geometric reasoning is identical.

Boundary zero represents an empty height or width, so the first prefix row and column are all zero. Allocate independent Kotlin rows with MutableList(n + 1) { MutableList(m + 1) { 0 } }.

Preprocessing: O(nm) time and space. Each query: O(1). The matrix stays unchanged.
